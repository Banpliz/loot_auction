# Аукцион лута — статус на 2026-08-26

Telegram Mini App: админ грузит скриншоты внутриигрового аукциона, приложение
режет их на лоты, определяет цвет редкости и пытается распознать
название/цену (OCR), пользователи делают ставки, админ разыгрывает победителей
с лимитами по цвету.

## Стек

Fastify + better-sqlite3 + sharp + tesseract.js (OCR) + ваниль TS/Vite
фронтенд, Telegraf-бот. Auth — Telegram initData (HMAC).

## Важная особенность машины

На этой Windows-машине **нет инструментов сборки** (Visual Studio Build
Tools). `npm install`/`npm uninstall` без явной нужды может попытаться
пересобрать нативные модули (`better-sqlite3`) и **снести node_modules
целиком** — уже случалось один раз в этой сессии. Ставить новые зависимости —
только по одной, сразу проверяя, что тесты/сборка не сломались.

## Схема БД (текущая)

`users`, `events`, `screenshots` (event_id, original_path, rows, template,
uploaded_by), `items` (event_id, screenshot_id, name, price TEXT, color TEXT:
blue/purple/red, image_path, status, winner_telegram_id), `claims`. Таблиц
`settings`/`price_tiers`/`catalog_items` больше нет — убраны за ненадобностью.

## Правило лимитов побед (зашито в коде, не настраивается)

В `src/server/routes/events.ts`: фиолетовый+красный вместе — максимум **1**
победа на человека за ивент, синий — максимум **2**. Ставок можно делать
сколько угодно, лимит только на выигрыш.

## Калибровка распознавания (`src/server/layout-templates.ts`)

Координаты для шаблонов `feast` (Пир победы) и `invasion` (Аукцион
вторжения) подобраны **на глаз** по реальным скриншотам, которые прислал
пользователь (не измерены по пикселям — не было доступа к файлам напрямую).
`contentTop` — какую долю скриншота сверху пропустить (шапка с золотом/
пандой/таблицей) перед тем как резать на строки: 0.43 для feast, 0.5 для
invasion. Если распознавание систематически промахивается — надо спросить
у пользователя конкретный пример и подправить координаты в этом файле.

## Открытая проблема: нестабильная загрузка скриншотов

Симптом: при загрузке реальных скриншотов с телефона через ngrok — ошибка 503
/ "Premature close", иногда "нихуя не загрузилось". Диагностировано: файл
физически не долетает до сервера (на диске не остаётся даже частичного
файла), т.е. дело не в размере файла и не в скорости обработки на сервере, а
в нестабильности/медленности самого канала телефон↔ngrok.

Уже сделано (в `web/views/eventDetail.ts` и `src/server/routes/screenshots.ts`):
- Ответ сервера отдаётся сразу после нарезки, OCR/цвет — в фоне (не блокирует
  ответ).
- Загрузка нескольких скринов — по одному запросу на файл, последовательно
  (не одним огромным запросом).
- Сжатие скриншота в браузере перед отправкой (JPEG, ширина до 720px,
  качество 0.7).
- Автоповтор при обрыве — до 3 попыток на файл с паузой.

Это снижает вероятность обрыва, но **не гарантирует** результат, если сама
сеть очень плохая — тут дело не в коде. Пользователю рекомендовано:
попробовать на Wi-Fi; если и там плохо — переходить на нормальный хостинг
вместо связки "локальный комп + бесплатный ngrok" (конфиги для этого уже
есть в `deploy/`).

## Как продолжать

1. Синхронизировать состояние: `git status --short` в обоих местах (воркспейс
   и `C:\Users\zelik\Documents\клуд`) — воркспейс обычно немного впереди
   основной папки уже закоммиченного/скопированного кода.
2. Перед любым рестартом живого сервера — искать его процесс через
   `Get-CimInstance Win32_Process -Filter "Name='node.exe'"` и не путать со
   вспомогательными Vite/ngrok процессами.
3. После правок backend — обязательно `npx vitest run` + `npx tsc --noEmit` в
   обоих местах перед копированием и рестартом.
